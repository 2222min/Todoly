## 1. 기술 스택 확정

### iOS
| 항목 | 결정 | 이유 |
|------|------|------|
| 언어 | Swift 5.9+ | 최신 안정 버전 |
| UI | SwiftUI | 기획안 요구사항, iOS 16+ 타겟 |
| 로컬 DB | UserDefaults + Codable | 경량 영속화, SwiftData 대비 단순 (v1 기준 충분) |
| 네트워크 | URLSession + async/await | 외부 의존성 최소화 |
| 인증 | AuthenticationServices (Apple) + GoogleSignIn SDK | 기획안 요구사항 |
| 알림 | UNUserNotificationCenter | 로컬 알림 (서버 푸시는 v1.1) |
| 아키텍처 | 레이어드 + Feature 기반 모듈화 | 순수 함수 분리, Protocol DI, SRP 적용 |
| 최소 버전 | iOS 18.0 | 기획안 v5 확정 (Liquid Glass는 iOS 26+, fallback 제공) |

### 서버 (v1 경량화 — 비용 최소화)

> **v1 핵심 전략**: Firebase 기반 서버리스. 별도 서버 인프라 비용 0원 (무료 티어 범위).
> 사용자 수 증가 시 v2에서 자체 서버로 마이그레이션.

| 항목 | 결정 | 이유 |
|------|------|------|
| BaaS | **Firebase** | 무료 티어 충분 (Spark Plan), 서버 구축/운영 비용 0원 |
| 인증 | **Firebase Auth** | Apple/Google/이메일 로그인 내장, SDK 한 줄 연동 |
| DB | **Cloud Firestore** | NoSQL, 실시간 동기화 내장, 오프라인 모드 자동 지원 |
| 스케줄러 | **Cloud Functions (scheduled)** | 휴지통 30일 삭제, 무료 티어 월 200만 호출 |
| 푸시 알림 | **v1에서는 로컬 알림만** | 서버 푸시는 v2에서 FCM 추가 |
| 인프라 비용 | **월 $0** (무료 티어) | Firestore 1GB 저장, 5만 읽기/2만 쓰기/일 |

#### Firebase 무료 티어 (Spark Plan) 범위
| 리소스 | 무료 한도 | Todoly 예상 사용량 |
|--------|----------|------------------|
| Firestore 저장 | 1 GB | 초기 사용자 ~1,000명 충분 |
| Firestore 읽기 | 50,000/일 | 충분 |
| Firestore 쓰기 | 20,000/일 | 충분 |
| Auth 사용자 | 무제한 | - |
| Cloud Functions | 200만 호출/월 | 스케줄러 1일 1회 = 월 30회 |

#### v1 → v2 마이그레이션 계획
- 사용자 1,000명 초과 또는 무료 티어 한도 도달 시
- Firestore → PostgreSQL + 자체 API 서버로 전환
- Firebase Auth는 유지 가능 (또는 자체 JWT로 전환)

## 2. Firestore 데이터 구조 (NoSQL)

```
users/{userId}
  ├── email: string
  ├── name: string
  ├── provider: "apple" | "google" | "email"
  ├── createdAt: timestamp
  │
  ├── todos/{todoId}
  │     ├── title: string
  │     ├── memo: string?
  │     ├── dueDate: timestamp?
  │     ├── priority: "high" | "medium" | "low" | "none"
  │     ├── categoryId: string?
  │     ├── categoryName: string?       // 비정규화 (조인 불필요)
  │     ├── categoryColor: string?      // 비정규화
  │     ├── isCompleted: boolean
  │     ├── completedAt: timestamp?
  │     ├── isDeleted: boolean
  │     ├── deletedAt: timestamp?
  │     ├── createdAt: timestamp
  │     ├── updatedAt: timestamp
  │     │
  │     └── reminders/{reminderId}
  │           ├── reminderDate: timestamp
  │           ├── type: "none" | "onTime" | "before" | "custom"
  │           ├── beforeMinutes: number?
  │           ├── isEnabled: boolean
  │           └── createdAt: timestamp
  │
  ├── categories/{categoryId}
  │     ├── name: string
  │     ├── color: string (HEX)
  │     ├── todoCount: number           // 비정규화 (카운트 쿼리 절약)
  │     └── createdAt: timestamp
  │
  └── searchHistory/{historyId}
        ├── keyword: string
        └── searchedAt: timestamp
```

> **비정규화 포인트**: Todo에 categoryName/categoryColor를 중복 저장하여 카테고리 조인 없이 리스트 렌더링 가능. 카테고리 수정 시 해당 Todo들도 일괄 업데이트 (batch write).

## 3. iOS에서 Firebase 연동

### SDK 설치 (SPM)
```
firebase-ios-sdk:
  - FirebaseAuth
  - FirebaseFirestore
  - FirebaseFirestoreSwift   // Codable 지원
```

### 인증 (Firebase Auth)
```swift
// Apple 로그인
Auth.auth().signIn(with: appleCredential)

// Google 로그인
Auth.auth().signIn(with: googleCredential)

// 이메일 로그인
Auth.auth().signIn(withEmail: email, password: password)
```

### CRUD (Firestore)
```swift
// 할 일 추가
let ref = db.collection("users").document(userId)
             .collection("todos").document()
try await ref.setData(from: todo)

// 할 일 목록 (실시간 리스너 — 자동 동기화)
db.collection("users").document(userId)
  .collection("todos")
  .whereField("isDeleted", isEqualTo: false)
  .order(by: "createdAt", descending: true)
  .addSnapshotListener { snapshot, error in
      // UI 자동 업데이트
  }

// 오프라인 모드 (Firestore 기본 내장)
let settings = FirestoreSettings()
settings.isPersistenceEnabled = true  // 기본값 true
settings.cacheSizeBytes = 100_000_000 // 100MB
db.settings = settings
```

> **오프라인 동기화가 자동**: Firestore SDK가 로컬 캐시 + 온라인 복귀 시 자동 동기화를 내장하고 있어, 별도 SyncService 구현 불필요.

## 4. iOS 앱 구조 (레이어드 아키텍처 + Feature 기반 모듈화)

> **2026-04-26 리팩토링**: 플랫 구조에서 레이어드 아키텍처로 전환. 순수 함수 분리, Protocol 기반 DI, SRP 적용.

```
Todoly/Todoly/
├── App/                          # 앱 진입점, 라우팅
│   ├── TodolyApp.swift           # @main, Scene 구성
│   ├── AppDelegate.swift         # UNUserNotificationCenterDelegate
│   ├── AppState.swift            # 앱 전역 상태 (splash → login → main)
│   └── RootView.swift            # AppState 기반 화면 라우팅

    ├── Alarm/AlarmView.swift     # 풀스크린 알람 (커스텀 사운드 + 진동)
```

### 의존성 방향 (위반 금지)
```
Features ──→ Domain ←── Data
    │            ↑
    └──→ Core ───┘
App ──→ 전체
```
- Domain은 어디에도 의존하지 않는다 (순수 레이어)
- Features끼리 직접 의존하지 않는다 (Store를 통해 간접 통신)

### 핵심 패턴: Store → 순수 로직 호출 → 결과 적용
```swift
// TodoStore.swift
func toggleComplete(_ todo: Todo) {
    let result = TodoMutationLogic.toggleComplete(todoId: todo.id, incomplete: incomplete, completed: completed)
    incomplete = result.incomplete   // 결과 적용
    completed = result.completed
}
```

> **삭제된 레이어**: APIClient, Repository, SyncService, ViewModel → Firestore SDK가 네트워크/캐시/동기화를 처리하고, Store가 순수 로직을 직접 호출하므로 별도 ViewModel 불필요.
